## PR mechanics — what rejects a PR before a human looks

| Item | Finding (source) |
|---|---|
| Workflow | **Fork only.** PR from `yuzhiquan/nvke`, never a branch on `dsx-ai-factory/nvke` (CONTRIBUTING, AGENTS) |

| Signatures | `main` ruleset includes **`required_signatures`**; `needs-signed-commits` label + comment when missing. `commit.gpgsign` unset here |
| Branch rules on `main` | `required_linear_history`, `pull_request`, `required_status_checks`, `commit_message_pattern`, `required_signatures`, `non_fast_forward` (live API) |
| Title | squash-merge → **PR title is the commit subject**. Pattern: `^(feat\|fix\|docs\|style\|refactor\|perf\|test\|build\|ci\|chore\|revert)(\([a-z0-9/_.-]+\))?!?: .+` (live ruleset). `pr-title` check is advisory |
| Breaking change | `!` after type or `BREAKING CHANGE:` footer; **no label** for it |
| Category label | one of `feature` / `bug` / `documentation` (CONTRIBUTING). Whether an outside contributor can set it: unverified |
| Body | `.github/pull_request_template.md`: Summary, Motivation (`Closes: #N` or `N/A`), Type, Component, Testing, Risk, Checklist. No CI format check found for the body; unverified beyond the title/DCO/signature workflows I read |
| Issue-first | needed for any non-trivial change. PR #2240 (open) would require a linked issue on every PR |
| AI policy | **disclose** in the PR when a substantial portion is AI-generated (write it yourself); **no** `Co-Authored-By` agent trailer, **no** "Generated with" footer; no AI-generated security/legal text or license headers |
| Merge gate | one aggregate required check `gate` (`merge-gate.yml`) + the DCO app; CODEOWNERS review required (`require_code_owner_review`), default owner team `@dsx-ai-factory/nvke-write` |

| Rebase mid-review | not forbidden: CONTRIBUTING documents `git rebase --keep-base --signoff` / `--gpg-sign` fixes |
